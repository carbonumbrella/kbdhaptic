# kbdhaptic

Виброотклик экранной клавиатуры и управление проводником с геймпада для портативных
ПК на Windows 11 (собрано и проверено на MSI Claw 8 AI+).

- **Вибро на набор:** короткий виброимпульс контроллера на каждый тап по клавише
  экранной клавиатуры. Вне клавиатуры (рабочий стол, игры, прокрутка) тишина.
- **Набор геймпадом:** поддерживается раскладка сенсорной клавиатуры "Игровая
  приставка", виброотклик срабатывает и при наборе текста геймпадом.
- **Геймпад в проводнике:** пока активно окно проводника, геймпад управляет им
  (каждое действие с вибрацией): **A** открыть, **Y** уровень вверх, **B** назад,
  **X** контекстное меню.
- **Автоповорот экрана:** на хендхелдах, где датчик отдаёт только Simple Device
  Orientation без акселерометра, штатный автоповорот Windows не включается.
  kbdhaptic читает датчик сам и поворачивает экран. Тумблер "Автоповорот" в быстрых
  настройках Windows работает как замок.
- Работает в фоне из трея, без прав администратора, в простое около 0% CPU.

## Как работает

Низкоуровневый хук клавиатуры ловит инжектированные нажатия экранной клавиатуры. Пока
клавиатура видима (`IFrameworkInputPane`), каждый тап даёт виброимпульс XInput (мотор
выключается по таймеру). Действия в проводнике опрашивают XInput только когда окно
проводника активно. Детект по области и видимости клавиатуры, а не по отдельным клавишам.

Проверено на хендхелде с Intel Arc (Lunar Lake). Нужен XInput контроллер (слот 0) и
.NET Framework 4.x (есть в Windows по умолчанию).

Автоповорот: отдельный поток читает датчик Simple Device Orientation (через WinRT по
рефлексии, поэтому встроенному компилятору не нужен winmd) и поворачивает экран вызовом
`ChangeDisplaySettingsEx`. Штатный автоповорот Windows на таких хендхелдах не работает,
потому что система подписывается на акселерометр/fusion-сенсор, а датчик их не отдаёт
(только квантованную ориентацию). Значение `AutoRotation\Enable` в реестре читается как
замок: тумблер "Автоповорот" в быстрых настройках Windows включает и выключает поворот.

## Установка

Скачай папку `release` (или архив релиза) и запусти **Install.cmd**. Он удалит прошлую
версию, установит в `%LOCALAPPDATA%\kbdhaptic`, повесит автозапуск по входу в систему
(без прав администратора) и запустит. В конце установщик предложит включить автоповорот
(импорт `Enable-AutoRotate.reg`, см. ниже) с запросом прав администратора. **Uninstall.cmd**
всё удаляет. Настройки в `kbdhaptic.ini` сохраняются при обновлении.

## Автоповорот экрана

Чтобы поворот заработал, Windows должен считать устройство планшетом и показывать тумблер
"Автоповорот". Это включается файлом **Enable-AutoRotate.reg** (ставит `SlateEnable`,
`SensorPresent`, `Enable` под `HKLM\...\AutoRotation`): импорт двойным кликом с правами
администратора, затем перезагрузка или перезаход. Установщик предлагает сделать это сам.

Пока эти флаги не выставлены, опция автоповорота в настройках **заблокирована** (серая) и
экран не поворачивается. Сам поворот делает kbdhaptic, а не Windows.

## Настройки

Двойной клик по иконке в трее:

- **Вибрация:** Малый мотор (R) и Большой мотор (L), длина импульса (1-40 мс), кнопка
  Тест и поле для проверки ввода.
- **Проводник:** переключатель "Кнопки геймпада в проводнике".
- **Экран:** переключатель "Автоповорот экрана" (заблокирован, пока не включена поддержка
  в Windows, см. раздел выше). Калибровка направления в `kbdhaptic.ini`: `rotateMap`
  задаёт соответствие ориентации датчика (NotRotated, 90, 180, 270) и ориентации дисплея
  (0..3); дефолт `0,3,2,1` подобран под панель Claw 8.

Все настройки лежат в `kbdhaptic.ini` рядом с программой и применяются сразу.

## Сборка

Запусти **build.cmd** (использует встроенный в .NET Framework компилятор C#, Visual
Studio не нужен). Результат в `release/kbdhaptic.exe`.
